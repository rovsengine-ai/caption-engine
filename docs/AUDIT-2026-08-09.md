Substantively working, with the file that implements it:

- **Vendor-neutral transcript schema** (`src/types.ts`) — `Word` carries text,
  start, end, confidence, type, language, and downstream `roman` / `isFiller` /
  `isFalseStart` / `keep`.
- **Three ASR adapters** normalising into that schema (`src/asr/`: elevenlabs,
  deepgram, sarvam) — offline-tested against stubbed `fetch` only.
- **Language-code normalisation** — `hin→hi`, `kan→kn` etc.
  (`src/config/language-codes.ts`, 199 assertions in `language-codes.test.ts`).
- **Language + script detection with explicit override**
  (`src/transliterate/detect.ts`). `--language` wins unconditionally; ASR tag
  second; dominant script third; the ambiguity of "script ≠ language" is
  surfaced in `alternatives` and `warnings` rather than hidden.
- **Transliteration capability matrix** (`src/transliterate/capabilities.ts`)
  for `local | sarvam | http | native`, checked *before* any request.
- **Glossary-first romanisation pipeline** (`src/transliterate/index.ts`) with
  per-token `TokenDiagnostic` stages, protected-English enforcement raised as a
  hard error, and a final "no Indic survives into Roman output" assertion.
- **`--roman-fallback error|native|http`**, default `error`; native passthrough
  is reported via `keptNativeScript` / `fallbackUsed`, never silent.
- **Sarvam strict token-count validation + bounded retry + per-batch stats**
  (`src/transliterate/providers.ts`, `batching.ts`) — 786 lines of test in
  `sarvam-batching.test.ts` covering mismatch, malformed JSON, 429 + Retry-After,
  concurrency bounds, and unchanged-response handling.
- **Auto Trim with reviewable cut records** (`src/autotrim/`) — `id`, `category`
  (aliased to `reason`), `label`, `confidence`, `sourceWords`, `wordIndices`,
  `start`, `end`, `restored`. `--review-cuts`, `--cuts-out`, `--cuts-in`,
  `--min-cut-confidence` all exist and are tested.
- **The three Auto Trim safety fixes are already in**: real words removed from
  the `always` filler tier; a *missing* neighbour counts as gap `0`, not
  `Infinity`; deliberate repetition requires a seam pause before it is called a
  false start.
- **Cut smoothing groundwork**: `applyHandles` (default 40 ms), `snapCutsToFrames`
  (start ceil / end floor, so it only ever cuts *less*), and a
  `DEFAULT_CUT_FADE_SEC = 0.012` fade in the FFmpeg filter graph — 21 tests in
  `smooth-cuts.test.ts`.
- **Rendering**: SVG/ASS caption generation, HarfBuzz shaping, resvg-first
  rasteriser with a functionally-probed FFmpeg fallback, chunked long-form
  render, atomic output with `ffprobe` validation.
- **12 vendored Noto font families** covering Devanagari, Telugu, Kannada, Tamil,
  Malayalam, Bengali, Gujarati, Gurmukhi, Oriya, Nastaliq and Latin.
  `doctor` proves each one resolves and that `विद्या` shapes to 4 glyphs with the
  matra reordered.
- **Input fingerprinting / cache-key invalidation** (`src/config/fingerprint.ts`)
  with `--allow-stale`, so a replaced video with the same filename does not
  silently reuse the old transcript.

### 8.1 `auto-cut-agent-main` — genuinely useful

`extension/js/core.js` (331 lines) is pure, dependency-free, side-effect-free
silence-cut planning. It is the closest thing to a reference implementation of
what Phase 2 needs.

| Concept | Where | Why it is better than what we have |
|---|---|---|
| `parseSilenceDetect()` | core.js:66 | Parses FFmpeg `silencedetect` stderr, incl. the case where a silence runs to EOF and ffmpeg logs no `silence_end`. We have **no** audio-based silence detection at all. |
| `parseVolumeDetect()` + `suggestNoiseFloor()` | core.js:90-120 | Derives the threshold from the file's own `mean_volume`, biased 6 dB down, clamped to −60…−20 dB and never above `max_volume − 12`. Fixes "a fixed dB threshold is wrong for every recording". |
| `absorbShortKeeps()` | core.js:176 | Merges cuts that would leave a useless sub-`minKeep` sliver between them. We have `mergeOverlapping` but nothing for near-misses — this is the direct fix for "cuts sound abrupt / machine-gun micro-cuts". |
| `mergeRanges(within)` | core.js:163 | Merge-within-slack, distinct from merge-on-overlap. Same purpose. |
| Footage presets | core.js:37-56 | talking-head / interview / screencast / aggressive, each with its own `minSilence`, `padding`, `mergeWithin`, `minKeep`. Better UX than one `--trim-silence` number. |
| `normalizeParams()` | core.js:296 | Clamps every knob to a range FFmpeg can honour. |

**Already independently solved here, do not copy:** `snapToFrame`/`snapRange`
(core.js:198-213) is the same ceil-start / floor-end rule as our
`snapCutsToFrames`, and `EPS = 0.012` matches our `DEFAULT_CUT_FADE_SEC`.
Convergent design, which is mild evidence both are right.

**Incompatible:** everything in `extension/jsx/host.jsx` (912 lines) is
ExtendScript against Premiere's undocumented QE DOM, and `main.js` is CEP panel
UI. Irrelevant to a CLI. The right-to-left cut application in `planCuts` is a
Premiere-timeline concern; our FFmpeg `keepSegments` approach is better for a
file-based renderer.

**Reusable tests:** `scripts/test.js` (474 lines) is plain Node with no
framework — the `silencedetect` parsing cases in particular port directly to
`node --test`.

### 8.2 `premiere-auto-captions-main` — mostly not useful, one idea worth stealing

`extension/js/core.js` is only 164 lines: SRT timecode formatting, cue merging,
and Whisper/OpenAI prompt construction. Our `src/captions/` already does the

The one thing worth taking is **conceptual, not code**: the

**Do not copy:** the `.epr` audio preset, the CEP panel, `server/index.js`

## 9. Honest scope assessment

You have listed eight phases. Phase 1 is largely done; Phases 2, 3, 4, 5 and 6
are each a new subsystem with its own test surface. Attempting all of it in one
pass would produce a large unreviewable diff and a high chance of regressing the
768 tests that currently pass — which is the one asset worth protecting.

Recommended order, each ending in a green build and its own commit:

1. **Phase 0 hygiene** — fix the index, the lock, the ignore rules. ~15 min, no code.
2. **Phase 2** — the two-pass filler/silence analyser. This is where your actual
   complaints live ("aaa", "a", abrupt cuts) and where `/ez` gives us the most.
   Largest single piece.
3. **Phase 1 remainder** — the extra `Word` fields, user glossary files, the
   `never` filler tier, more regression fixtures. Small.
4. **Phase 4** — J/L cuts, on top of the handle/fade/snap machinery that exists.
5. **Phase 6** — templates. Self-contained, low risk, high visible payoff.
6. **Phase 3 + 5 Stage A** — local visual analysis. Big, and only useful once
   Phase 2's cut records exist to attach visual decisions to.
7. **Phase 5 Stage B** — external provider adapters, behind cost gates, tested
   against fake HTTP servers only.
